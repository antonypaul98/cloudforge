# Private staged-source pre-build recheck (bounded demo prerequisite)

The existing selected-source OCI staging module already creates a mode 0700 temporary directory and mode 0600 source/manifest files. Its pre-build verification previously checked filenames, regular file type, no-follow opens and SHA-256 but did not reject a staging directory made accessible to other users, files made group/world-readable, or hardlinks created outside the staging directory. Such substitutions could expose selected source or manifests without changing their hashes.

This checkpoint reuses the existing Python 3.11 `os.fstat`, `os.geteuid`, `stat.S_IMODE` and `st_nlink` contracts. It requires the staged directory to remain owned by the effective user with mode 0700, and each expected file to remain owned by that user, have exactly one hard link, and have no group/other permission bits. It checks these attributes through the already-open directory/file descriptors before digesting bytes. Tests exercise normal Python/Node packages, exposed directory, exposed source and manifest, outside hardlinks, and existing symlink/nonregular/changed-byte rejection. The rootless OCI PR workflow now triggers when the staging module or its regressions change.

Reuse-first: no third-party code copied or translated; no new dependency, license, API key, provider cost or cloud permission. The relevant standard-library contracts are documented at https://docs.python.org/3.11/library/os.html and https://docs.python.org/3.11/library/stat.html. The alternative of building a new staging system was rejected in favor of strengthening the existing verified package boundary.

**Limitations:** This remains a point-in-time pre-build check, not immutable storage or a TOCTOU-free sandbox. It does not prevent a same-user process changing files after verification, prevent access by a privileged process, authenticate a human, authorize an external selected application, sign external health evidence, or deploy/roll back infrastructure. The real OCI CI still executes only CloudForge's pinned first-party Python fixture under synthetic keys. Do not treat this as approval to execute untrusted selected code.

Acceptance requires exact-head Python 3.11 product and infrastructure tests, the real rootless OCI PR job, a guarded merge, merged-main CI and canonical checkpoint publication. Roll back the software changes by reverting the feature merge; no persistent schema, production resource or credential changes are involved. Demo readiness remains partial; full-product completion is unverified.
